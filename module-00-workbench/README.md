# Module 00 · The workbench

Before cooking, you set up the kitchen: you find the knives, the pans, the cutting board. Before programming, you set up your **workbench**: the terminal, Python itself, and a tidy way to organize your files.

This module has very little "real" programming. That is on purpose. When the tools feel familiar, the code feels much less scary.

## Goals

By the end of this module you will be able to:

- Open a terminal and move between folders with `pwd`, `ls` and `cd`.
- Run a Python file from the terminal with `python file.py`.
- Explain the difference between writing a file and running it.
- Read an error message and find the line where the problem is.
- Keep your projects organized in one predictable place.
- Write simple notes in Markdown.

## Files, in order

1. [terminal.md](terminal.md): talking to the computer with text commands.
2. [python.md](python.md): what Python is and how to run it.
3. [software-engineering.md](software-engineering.md): habits that keep your work tidy.

## You are ready for the next module when...

- [ ] You can open a terminal and say which folder you are in without guessing.
- [ ] You can go into a folder, come back out, and list what is inside.
- [ ] You can create a `.py` file, save it, and run it from the terminal.
- [ ] You know the difference between typing `python` and typing `python hello.py`.
- [ ] When you see an error, you look at the line number and the last line of the message first.
- [ ] All your course files live inside one `Projects` folder, with names that have no spaces or accents.
- [ ] You have a notes file in Markdown with at least one heading and one code block.
